MODULE 7 · TESTING + MAINTAINABILITY · LESSON 1

Tests that catch

One sitting, one win: your service logic is proven by tests that run in milliseconds — no server, no database.

⏱ 30–40 minPrerequisites: Module 6 gateObjectives: runner · unit · services
The real problem. Every refactor so far was verified by hand-knocking endpoints — slow, forgetful, unrepeatable. The first time you rename a service function, silence replaces proof. Tests are proof that runs itself: structure (chart 57) finally pays off, because services take data in and return data out — testable with zero HTTP.

1 · The mental model: pyramid, not ice cream

Chart 102 — Pyramid. Wide base of fast unit tests, thin tip of slow journeys. Inverted (all E2E) means every run costs minutes and flakes constantly.

Source + speed law (click)

Law: a test you won't run is decoration — unit suites must finish in seconds or developers stop running them. Services (pure logic, chart 57) are the base because they need no server, no DB, no network. Source: Node test runner (built-in, zero deps).

unit (services) → integration (HTTP) → e2e (browser, later)

4 · Live demo: suite in 20 lines (10 min)

Create services/tasks.service.test.mjs — imports the real service, no server booted:

// file: services/tasks.service.test.mjs
import { test } from "node:test";
import assert from "node:assert/strict";
import { listTasks } from "./tasks.service.mjs";

const rows = [
  { id: "a", title: "Zebra", done: false, createdAt: 3 },
  { id: "b", title: "Apple", done: true, createdAt: 2 },
  { id: "c", title: "Mango", done: false, createdAt: 1 },
];
test("filters by done", () => {
  const { data, total } = listTasks(rows, { done: "false", page: 1, limit: 10 });
  assert.equal(total, 2);
  assert.deepEqual(data.map((t) => t.id), ["a", "c"]);
});
test("sorts by title desc + pages", () => {
  const { data, total } = listTasks(rows, { sort: "title", order: "desc", page: 1, limit: 2 });
  assert.equal(total, 3);
  assert.deepEqual(data.map((t) => t.title), ["Zebra", "Mango"]);
});
test("search narrows, miss empties", () => {
  assert.equal(listTasks(rows, { q: "app", page: 1, limit: 10 }).total, 1);
  assert.deepEqual(listTasks(rows, { q: "zzz", page: 1, limit: 10 }).data, []);
});
node --test services/
# expected: pass 3, fail 0 — milliseconds. Break listTasks on purpose, re-run: red names the branch.

Why it works: node:test ships with Node (no install, runs *.test.mjs); assert/strict deep-compares (references lie, values don't). Services take arrays, so tests hand-craft rows — the payoff of chart 57's split, finally collected.

5 · How this fits TaskFlow

Base of the pyramid poured: every future service change runs this suite first (seconds, always). 0033 knocks HTTP for real (integration layer); the pyramid stays green-expandable — new branch, new case, same file.

6 · Common mistakes

“Testing through HTTP only.” Every assertion boots server + DB — suite takes minutes, nobody runs it. Fix: logic in services, services tested directly; HTTP tests assert wiring, not math.
“assert.equal on objects.” Passes on same reference, fails on equal values — both lies. Fix: deepEqual for data, equal for scalars. Know which you mean.
“No failing-first run.” Suite written after code, never seen red — it may assert nothing (empty test passes!). Fix: break the function once, watch red, then fix. Red-green isn't ritual, it's calibration.
