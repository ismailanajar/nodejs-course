Docs true, types catching

One sitting, one win: your API describes itself (OpenAPI) and your editor catches shape bugs (TypeScript).

⏱ 30–40 minPrerequisites: Lesson 0033 (matrix green)Objectives: openapi · ts basics
The real problem. The contract (lesson 0004's menu) now lives in three places — Zod schemas, test assertions, and your memory — and they've already drifted twice. Docs rot because writing is separate from code; types rot nothing because the compiler re-checks every keystroke. Today: one description generated from truth, plus types where they pay most.

4 · Live demo: served docs + first types (10 min)

npm install swagger-ui-express zod-to-openapi
# openapi.json generated from your Zod schemas (script below) → served at /docs:
// file: docs.mjs — schemas → OpenAPI (run at startup, served fresh)
import { OpenApiGeneratorV3 } from "@asteasolutions/zod-to-openapi";
import { taskCreate, taskUpdate } from "./schemas.mjs";
// register schemas once, generate document, serve:
const generator = new OpenApiGeneratorV3(/* registry with paths — see key */);
// minimal honest version (no new deps): hand-write openapi.json ONCE from schemas,
// then ADD A TEST asserting every room's path exists in it:
import { test } from "node:test";
import assert from "node:assert/strict";
import spec from "../openapi.json" with { type: "json" };
test("docs cover rooms", () => {
  for (const p of ["/health", "/tasks", "/tasks/{id}", "/auth/register", "/auth/login"])
    assert.ok(spec.paths[p], `missing ${p}`);
});
// types: rename db.mjs → db.mts? No — start with JSDoc + checkJs (zero migration):
// jsconfig: { "compilerOptions": { "checkJs": true, "strict": true }, "include": ["services/"] }

# npx tsc --noEmit → editor + CI catch wrong-shape callers. Full .ts migration: Module 8+ elective.

Why it works: the docs-coverage test turns drift into red (docs stay true because CI enforces); JSDoc types buy 80% of TypeScript with 0% migration — the pragmatic backend default.

5 · How this fits TaskFlow

Frontend integration (Module 8) codes against /docs, not memory; refactors run tests + types before humans review. The triangle is the maintainability story: judge (schemas), catch (types), prove (tests) — every future feature repeats it.

6 · Common mistakes

“Docs as screenshots.” Pretty, dead on arrival. Fix: generated or test-guarded docs only — anything else is lesson-0004 nostalgia.
“any everywhere.” Types that accept everything check nothing. Fix: any only at system edges with a TODO; strict everywhere else.
“TS rewrite week.” Halting features to convert everything. Fix: JSDoc-first, convert hot files only — types serve shipping, not the reverse.
