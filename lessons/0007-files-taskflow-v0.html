Files: memory that survives

One sitting, one win: your CLI adds tasks that are still there tomorrow — TaskFlow v0 is born.

⏱ 30–40 minPrerequisites: Lesson 0006 (argv)Objectives: fs read/write · JSON file · CLI routes
The real problem. Lesson 0006's tasks lived in variables — close the terminal and they evaporate. A task manager with amnesia is a toy. The fix is one idea: after every change, write the array to a file; on every start, read it back. That loop is 80% of what “persistence” will ever mean.

4 · Live demo: TaskFlow v0 (8 min)

Create tasks.mjs — ES modules import with the node: prefix (built-in, zero install):

// file: tasks.mjs
import { readFile, writeFile } from "node:fs/promises";

const FILE = new URL("./tasks.json", import.meta.url);
const [cmd, ...rest] = process.argv.slice(2);

async function load() {
  try {
    return JSON.parse(await readFile(FILE, "utf8"));
  } catch {
    return []; // first run: no file yet — start empty
  }
}
async function save(tasks) {
  await writeFile(FILE, JSON.stringify(tasks, null, 2));
}

if (cmd === "add") {
  const title = rest.join(" ").trim();
  if (!title) { console.error("usage: node tasks.mjs add \"Buy milk\""); process.exit(1); }
  const tasks = await load();
  const task = { id: Date.now(), title, done: false };
  await save([...tasks, task]);
  console.log(JSON.stringify(task));
} else if (cmd === "list") {
  const tasks = await load();
  for (const t of tasks) console.log(`${t.done ? "[x]" : "[ ]"} ${t.id} ${t.title}`);
} else {
  console.log('usage: node tasks.mjs add "TITLE" | node tasks.mjs list');
}
node tasks.mjs list
# expected (first run): (no output — empty list, file not yet born)
node tasks.mjs add "Buy milk"
# expected: {"id":1729...,"title":"Buy milk","done":false}
node tasks.mjs list
# expected: [ ] 1729... Buy milk  ← survived! close the terminal, it stays
cat tasks.json
# expected: pretty array with your task — open it, it's readable by design

Why it works: try/catch turns “missing file” into “empty list” (error handling doing real work); Date.now() is a good-enough id for v0; process.exit(1) signals misuse to the terminal (chart 9's exit codes, lesson 0006).

5 · How this fits TaskFlow

v0 persists — crudely. Module 3 serves these same tasks over HTTP; Module 4 validates them with Zod; Module 5 moves them into PostgreSQL (same read-modify-write idea, professional tools). The file never scales to two users at once — that honest limit is exactly why databases exist, and you'll feel it before you're told it.

6 · Common mistakes

“Wrote tasks but list is empty.” You forgot await save(...) — the process exited before writing finished. Fix: every mutation ends with an awaited save; re-check chart 12's order.
“SyntaxError on load.” You hand-edited tasks.json and broke a comma. Fix: delete the file (it's dev data) or re-validate with node -e "console.log(JSON.parse(require('fs').readFileSync('./tasks.json','utf8')))" — better: stop hand-editing, use the CLI.
“Used fs sync / callbacks soup.” readFileSync blocks everything; nested callbacks tangle. Fix: node:fs/promises + await — the course default, matching how database drivers work later.
