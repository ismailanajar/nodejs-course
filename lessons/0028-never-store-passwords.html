MODULE 6 · AUTH + SECURITY · LESSON 1

Never store passwords

One sitting, one win: registration + login with hashed secrets — plaintext never touches the disk.

⏱ 35–45 minPrerequisites: Module 5 gateObjectives: hash · register · login
The real problem. Every breach headline is a plaintext (or MD5) password table. Hashing isn't encryption — it's a one-way fingerprint: verify by re-fingerprinting, never by decrypting. Today accounts become real, and the users table learns its most sacred column.

Source + slow law (click)

Law: hashing must be SLOW (100ms+) — speed helps attackers guessing billions, never your login UX. argon2id first choice (OWASP password storage), bcrypt everywhere-accepted second. Fast hashes (MD5/SHA-256 alone) are decoration, not protection. Salts are automatic in both — never hand-roll.

register: hash → store · login: hash attempt → compare (timing-safe)

Source + oracle rule (click)

Oracle rule: error text identical (“invalid credentials”), duration similar (hash a dummy on miss). Different messages (“no such user” vs “wrong password”) hand out a user directory. 0029 turns the SESSION box into cookies.

4 · Live demo: accounts (12 min)

npm install argon2
# migration 003_auth.sql: users table already exists from Prisma — add sessions next lesson.
# Raw-SQL version (transparent before Prisma hides it):
-- file: db/003_password.sql
ALTER TABLE users ADD COLUMN password_hash TEXT;
// file: routes/auth.routes.mjs (register + login, sessions stubbed → 0029)
import { Router } from "express";
import * as argon2 from "argon2";
import { z } from "zod";
import { query } from "../db.mjs";
export const authRouter = Router();
const creds = z.object({
  email: z.string().email().max(255),
  password: z.string().min(12, "min 12 chars").max(128),
});
authRouter.post("/register", async (req, res) => {
  const v = creds.safeParse(req.body);
  if (!v.success) return res.status(400).json({ error: "invalid input", issues: v.error.issues });
  const hash = await argon2.hash(v.data.password); // ~100ms of safety
  try {
    const { rows } = await query(
      "INSERT INTO users(email, password_hash) VALUES($1,$2) RETURNING id, email",
      [v.data.email, hash]);
    res.status(201).json(rows[0]);
  } catch (err) {
    if (err.code === "23505") return res.status(409).json({ error: "email taken" });
    throw err;
  }
});
authRouter.post("/login", async (req, res) => {
  const v = creds.safeParse(req.body);
  if (!v.success) return res.status(401).json({ error: "invalid credentials" });
  const { rows } = await query("SELECT * FROM users WHERE email=$1", [v.data.email]);
  const user = rows[0];
  const ok = user
    ? await argon2.verify(user.password_hash, v.data.password)
    : await argon2.hash(v.data.password).then(() => false); // dummy work, same time
  if (!ok) return res.status(401).json({ error: "invalid credentials" });
  res.json({ message: "session comes in 0029", user: { id: user.id, email: user.email } });
});
node app.mjs  # with app.use("/auth", authRouter)
node -e "const r = await fetch('http://localhost:3000/auth/register',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({email:'ada@example.com',password:'correct-horse-123'})}); console.log(r.status, await r.json())"
# expected: 201 { id, email } — NO hash in reply. Repeat → 409 email taken.
node -e "const r = await fetch('http://localhost:3000/auth/login',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({email:'ada@example.com',password:'nope-nope-nope!'}); console.log(r.status, await r.json())"
# expected: 401 { error:'invalid credentials' } — same shape for missing users too

Why it works: 23505 is Postgres for “unique violated” — the race-proof check (two simultaneous registers, one wins honestly). Async argon2 keeps the loop breathing (lesson 0010's stare warning, honored).

6 · Common mistakes

“Returned the hash.” 201 includes password_hash “for debugging”. Fix: SELECT explicit columns, never SELECT * on users near a response — allowlist what leaves.
“Sync hash in handler.” hashSync stares 100ms+ per login (chart 20's oven-stare, at scale). Fix: async forms only in servers — graded in Module 7 tests (slow suite tells on you).
“Different errors per case.” “No such user” vs “wrong password” — user enumeration oracle. Fix: one message, dummy work on miss, identical timing shape.
