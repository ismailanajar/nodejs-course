What your fetch call really sends

One sitting, one win: you read a real HTTP request and response line by line — nothing magic left.

⏱ 25–35 minPrerequisites: fetch basics + Lesson 0001 mapObjectives: method · path · headers · body · status
The real problem. You already write fetch("/api/tasks") — but when it breaks you stare at “failed to fetch” with no idea who is at fault: your URL, the server, or the network. Today that ends: every fetch is two plain-text messages, and you will read both.

1 · The mental model

Think restaurant: you hand the waiter an order slip (request: what + which dish + notes). The kitchen returns a tray (response: did it work? + the food). HTTP works exactly like that — two messages, always in this order:

sequenceDiagram participant B as Browser / fetch() participant S as Server API B->>S: REQUEST — method + path + headers + body S->>S: validate, decide, fetch data S->>B: RESPONSE — status + headers + body

Diagram C — One HTTP round trip. Arrows are messages travelling over the network; time flows downward.

How to read + walkthrough (click)

How to read: top to bottom = earlier to later. Solid arrows cross between programs. The middle line (server thinking) never leaves the server.

Walkthrough: ① your fetch() builds a request (say GET /todos/1) ② the server reads it, decides, maybe queries a database ③ it replies with a status (200 = ok) plus a JSON body. If step ① is malformed, step ③ is a 4xx — the kitchen rejecting a bad slip.

Takeaway: frontend and backend never share memory — only these two messages. Debugging = “which message is wrong?” Source: MDN HTTP overview.

2 · Anatomy of the two messages

PartRequest (you send)Response (you get)
Start lineGET /todos/1 HTTP/1.1 — method + pathHTTP/1.1 200 OK — status code + phrase
HeadersAccept: application/json — “I want JSON”Content-Type: application/json — “this IS JSON”
BodyEmpty on GET; JSON on POST/PUT/PATCHThe data — usually JSON for APIs

Three vocabulary facts that pay off forever: method = the verb (GET read, POST create, PUT/PATCH update, DELETE remove — MDN methods). Status = three digits grouped 2xx ok / 3xx redirect / 4xx your fault / 5xx server's fault (MDN status codes). JSON = the text format both sides parse with JSON.stringify / response.json().

3 · Live demo: see it with your own eyes (5 min)

A — browser (no install). Open DevTools → Network tab, then run this in the console:

await fetch("https://jsonplaceholder.typicode.com/todos/1")
  .then(async (r) => ({ status: r.status,
    type: r.headers.get("content-type"), body: await r.json() }))
// expected: { status: 200, type: "application/json; charset=utf-8",
//   body: { userId: 1, id: 1, title: "delectus aut autem", completed: false } }

Click that request in the Network tab: the Headers panel is the two messages from §2, raw.

B — Node (same idea, terminal side). Create request-demo.mjs — Node 24 already has global fetch, zero dependencies:

// file: request-demo.mjs
const res = await fetch("https://jsonplaceholder.typicode.com/todos/1");
console.log("status:", res.status);
console.log("content-type:", res.headers.get("content-type"));
console.log("body:", await res.json());
node request-demo.mjs
# expected:
# status: 200
# content-type: application/json; charset=utf-8
# body: { userId: 1, id: 1, title: 'delectus aut autem', completed: false }

Why it works: both demos send the identical request message and print the identical response message — browser or Node, the HTTP is the same. That is the whole Module 1 promise.

4 · How this fits TaskFlow

Every TaskFlow feature is one row in this table. “Show my tasks” = GET /tasks → 200 + JSON list. “Add a task” = POST /tasks with a JSON body → 201 Created. Module 3 will make you hand-build these messages; Module 4 gives you Express shortcuts. Today's job is only: recognize them on sight.

5 · Common mistakes

“fetch threw on 404.” No — fetch() only throws on network failure. A 404 still resolves; you must check res.status/res.ok yourself. Fix: always branch on status before res.json().
“Path vs query mixed up.” /tasks/7 = one specific task (route param); /tasks?done=false = filtered list (query). Fix: params identify, queries filter — Module 4 drills this.
“Sent JSON but server says 400/415.” You forgot Content-Type: application/json or sent a raw object instead of JSON.stringify(obj). Fix: set the header and stringify — the server can't guess your format.

6 · Practice exercise

  1. Run demo A above, open the request in DevTools Network tab.
  2. Write down: method + full path, status code (+ its group), 3 request headers, 3 response headers, body keys.
  3. Change the URL to .../todos/999999, re-run, note what status + body you get and which “fault group” it belongs to.

Done means: a sheet with both cases filled in, and one sentence saying which message (request or response) you would blame for each case.
