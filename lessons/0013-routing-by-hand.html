MODULE 3 · SERVER FROM SCRATCH · LESSON 2

One door, many rooms

One sitting, one win: your server answers three different endpoints — with the right status each time.

⏱ 30–40 minPrerequisites: Lesson 0012 (listen + reply)Objectives: route · query · 404 · JSON
The real problem. Hello-server answers every knock identically — GET /health and DELETE /everything get the same smile. A real API is a building: one door, many rooms, and a guard who says “no such room” with a 404. Today you become the guard, with bare hands.

4 · Live demo: three rooms (10 min)

Create server.mjs — every lesson-0004 shape, served raw:

// file: server.mjs
import http from "node:http";

const tasks = [
  { id: "a1", title: "Learn routing", done: true },
  { id: "b2", title: "Learn bodies", done: false },
];

function send(res, status, obj) {
  res.writeHead(status, { "content-type": "application/json" });
  res.end(JSON.stringify(obj));
}

const server = http.createServer((req, res) => {
  const { pathname, searchParams } = new URL(req.url, "http://base");
  console.log(`${req.method} ${pathname}`);
  if (req.method === "GET" && pathname === "/health") {
    return send(res, 200, { ok: true });
  }
  if (req.method === "GET" && pathname === "/tasks") {
    const done = searchParams.get("done");
    const list = done === null ? tasks : tasks.filter((t) => String(t.done) === done);
    return send(res, 200, list);
  }
  return send(res, 404, { error: `no such room: ${req.method} ${pathname}` });
});

server.listen(3000, () => console.log("listening on http://localhost:3000"));
node server.mjs
node -e "console.log(await (await fetch('http://localhost:3000/health')).json())"
# expected: { ok: true } — LEFT logs: GET /health
node -e "console.log(await (await fetch('http://localhost:3000/tasks?done=false')).json())"
# expected: [{ id: 'b2', ... }] — same room, filtered slice
node -e "const r = await fetch('http://localhost:3000/nope'); console.log(r.status, await r.json())"
# expected: 404 { error: 'no such room: GET /nope' } — the guard speaks

Why it works: return send(...) both replies and exits the handler — guaranteeing one response exactly (lesson 0012's rule, enforced by construction). Query filtering compares strings because URLs only carry text.

5 · How this fits TaskFlow

Three rooms today, full building soon: 0014 adds bodies (POST /tasks reads JSON text), 0015 wires the file behind the rooms (persistence returns). The send helper and the guard diamond survive all the way into Express — renamed res.json and “routes”, same bones.

6 · Common mistakes

“Query broke my route.” Compared raw req.url including ?.... Fix: always split first, route on pathname only — chart 33.
“Two replies / headers already sent.” Fell through past a send into another. Fix: return send(...) every branch — replying is also leaving.
“200 for the 404.” Right body, wrong status — clients branch on numbers, not text. Fix: the guard's trapdoor always 404; reserve 200 for rooms that exist.

7 · Practice exercise

  1. Add GET /tasks/:id by hand: split pathname on /, match two segments with first tasks — found → 200 + task, else 404 + error. Feel the pain; Express removes it in Module 4.
  2. Add ?limit=N to GET /tasks: slice the list; non-numeric N → 400 + error (your first “bad query” verdict).
  3. Paste: three knock outputs (item found, item 404, limit bad → 400) + the new code branches.

Done means: id room + limit filter + three correct statuses (200/404/400). Lesson 0014 (bodies: POST reads JSON) is next.
