NODE.JS BACKEND COURSE · STAGE 1

Course map: from fetch works to “I ship APIs”

One sitting, one win: you can draw the whole backend journey and know exactly where TaskFlow goes next.

⏱ 35–45 minPrerequisites: HTML/CSS/JS + fetch basics Objectives: request lifecycle · 8-module map · TaskFlow milestones · what to install
Start with a real problem. You can build a beautiful todo UI, but refresh the page and everything vanishes. Two users can't share anything. There is nowhere to check “is this person allowed to see this task?” — because everything lives in the browser. That missing half is the backend, and this course builds it piece by piece as TaskFlow.

How to read + walkthrough (click)

How to read: boxes are programs, arrows are messages. Follow the numbers: ① frontend sends HTTP request ② API validates, checks auth, runs logic ③ API queries Postgres ④ rows come back ⑤ API replies with status + JSON.

Beginner takeaway: the frontend never touches the database directly. If data survives refresh or is shared between users, it went through this loop. Full reference: MDN HTTP overview.

2 · What each piece actually is (no jargon debt)

Word (glossary)Plain-English meaningFrontend analogy
ServerA program that never quits; it waits for requests and answers them.Like an event listener that never gets removed.
PortA numbered door (e.g. 3000) where one server waits. localhost:3000 = “this laptop, door 3000”.Like a tab ID — same browser, different slot.
APIThe agreed request/response shapes: “GET /tasks returns a list”.Like a component's props contract.
PostgreSQL / PrismaPostgres stores rows durably; Prisma is a typed helper that writes safe SQL for you — after you learn SQL.Like localStorage, but shared, relational, and safe.

Stack lock for this course (verified Oct 2026 — see RESOURCES.md): Node 24 LTS “Krypton” (Node docs — v24 is LTS, v26 is Current), Express 5.x (needs Node 18+, Express 5 API), PostgreSQL 16/17 (PG tutorial), Prisma ORM 7 stable (v8 is release-candidate — we stay on 7, Prisma v7 Postgres), plus Zod, argon2/bcrypt, Node test runner + Supertest, Docker only for local DB + deploy.

5 · Live check: prove your machine is ready (2 min)

Create hello-backend.mjs and run it — this is the smallest “backend thought”: a program that computes and prints, no browser needed.

// file: hello-backend.mjs
const who = process.argv[2] ?? "future backend dev";
console.log(`hello ${who} — Node ${process.version}`);
node --version
# want v24.x (LTS). If v26, fine; if <20, upgrade via https://nodejs.org/en/download
node hello-backend.mjs Ada
# expected: hello Ada — Node v24.x.x

Why it matters: every later server is just this — a long-running Node process — plus “wait for HTTP on a port”. If this runs, Module 2 is already half-won.

6 · Common mistakes (save yourself an hour)

“localhost refused to connect.” Nothing is listening on that port (server not started, or wrong port). Fix: start the server first, then match the exact port in URL and fetch().
“I know Express but not HTTP.” Framework-first learning leaks. Fix: Module 3 forces raw node:http first so Express middleware order feels obvious later.
“I'll learn Prisma and skip SQL.” Then every relation bug is magic. Fix: Module 5 writes INSERT/SELECT/JOIN by hand before Prisma is allowed.
