Dials outside the code

One sitting, one win: your CLI reads config from the environment and fails with sentences, not stack traces.

⏱ 30–40 minPrerequisites: Lesson 0008 (project shape)Objectives: env vars · stderr/exit · friendly errors
The real problem. v0 hardcodes ./tasks.json — want a test file? Edit code. And when the JSON corrupts, Node vomits 20 lines of internals at a user who just wanted to list tasks. Both are the same sin: mixing what changes (config, problems) with what doesn't (logic).

Source + why it matters (click)

Why: node tasks.mjs list > out.txt captures only stdout — errors still reach your eyes via stderr. And echo $? (or CI checks) reads the verdict. Mixing them corrupts both: error text inside JSON output breaks every parser downstream.

Source + the translation rule (click)

Translation rule: catch at the boundary (where outside-world bytes enter), speak human (“tasks.json is corrupt — fix or delete it”), exit nonzero. Stack traces are for your debugging (keep them in dev with console.error(err) behind a flag), never for users. Source: Node.js — errors.

4 · Live demo: TaskFlow v0 behaves (8 min)

Two upgrades to db.mjs — a dial for the file, and a translator for corruption:

// file: db.mjs (upgraded)
import { readFile, writeFile } from "node:fs/promises";
const FILE = new URL(process.env.TASKS_FILE ?? "./tasks.json", import.meta.url);
export async function load() {
  let text;
  try {
    text = await readFile(FILE, "utf8");
  } catch {
    return []; // missing → first run, start empty
  }
  try {
    const data = JSON.parse(text);
    if (!Array.isArray(data)) throw new Error("not a list");
    return data;
  } catch {
    console.error(`error: ${process.env.TASKS_FILE ?? "./tasks.json"} is corrupt — fix it or delete it to start fresh.`);
    process.exit(1);
  }
}
export async function save(tasks) {
  await writeFile(FILE, JSON.stringify(tasks, null, 2));
}
TASKS_FILE=./demo.json npm run add -- "Test drive"
# expected: task saved into demo.json — tasks.json untouched. Same code, dial turned.
TASKS_FILE=./demo.json npm run list
echo "oops {{{" > demo.json
TASKS_FILE=./demo.json npm run list; echo "exit=$?"
# expected: error: ./demo.json is corrupt — fix it or delete it to start fresh. / exit=1
# (Windows PowerShell: $env:TASKS_FILE="./demo.json"; node tasks.mjs list)

Why it works: ?? keeps zero-setup behavior; the two nested try blocks separate “absent” (kind) from “broken” (firm); exit(1) tells the terminal the truth.

5 · How this fits TaskFlow

This dial is the ancestor of all configuration: Module 5's DATABASE_URL, Module 8's production secrets — same process.env.X ?? default shape, higher stakes (no defaults for passwords, .gitignore'd .env files via dotenv). The two-channel habit is what makes future servers log cleanly instead of spraying.

6 · Common mistakes

“Env var ignored.” You wrote TASKS_FILE = ./x.json with spaces, or set it after the command. Fix: NAME=value, no spaces, before the command (PowerShell: $env:NAME="value" on its own line).
“console.log for errors.” Error text pollutes piped JSON downstream. Fix: humans' bad news always via console.error + nonzero exit.
“Committed a secret.” API key pasted into code and pushed. Fix: it's compromised the second it touches git — revoke it, move it to a dial, add the file to .gitignore. Practice this with harmless paths now so it's reflex later.
