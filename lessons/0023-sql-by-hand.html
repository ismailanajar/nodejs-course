Ask questions, get rows

One sitting, one win: you write the four SQL verbs and slice lists without touching application code.

⏱ 30–40 minPrerequisites: Lesson 0022 (table exists)Objectives: CRUD verbs · filter/sort/page
The real problem. “Page 2 of unfinished tasks, newest first” in file-land means load-all, filter, sort, slice — hand-written every time, in every language, forever. In SQL it's one sentence the librarian optimizes. Four verbs + four clauses cover 90% of backend life; today you own them.

3 · Writes: say WHAT, not HOW

sequenceDiagram participant Y as you (psql) participant P as planner participant R as rows Y->>P: UPDATE tasks SET done=true WHERE id='a1' P->>P: find via key (no full scan) P->>R: change + report count R->>Y: UPDATE 1

Chart 71 — Declarative writes. You describe the target set (WHERE); the planner picks the path. The count back (“UPDATE 1”) is your affected-rows receipt — 0 means “matched nothing”, the SQL twin of 404.

Source + WHERE law (click)

Law: UPDATE/DELETE without WHERE touch every row — the most-feared beginner command in backend (DELETE FROM tasks; empties the table, no trash can). Say WHERE first, run SELECT with the same WHERE first when nervous.

UPDATE tasks SET done=true WHERE id='a1'; -- receipt: UPDATE 1

4 · Live demo: four verbs (10 min)

docker exec -it taskflow-db psql -U postgres -d taskflow
-- inside psql now (prompt: taskflow=#). Semicolons end every command; \q quits.
INSERT INTO tasks (id, title) VALUES ('a1', 'Learn SQL'), ('b2', 'Learn JOINs');
-- expected: INSERT 0 2
SELECT id, title, done FROM tasks ORDER BY created_at;
-- expected: 2 rows — your first question answered
SELECT * FROM tasks WHERE done = false ORDER BY created_at DESC LIMIT 10 OFFSET 0;
-- expected: page 1 of open tasks, newest first — chart 70 alive
UPDATE tasks SET done = true WHERE id = 'a1';
-- expected: UPDATE 1
DELETE FROM tasks WHERE id = 'b2';
-- expected: DELETE 1 — and a1 stays done. Verify: SELECT * FROM tasks;

Why it works: psql sends text, Postgres answers with receipts + rows. id omitted from INSERT would fail (no default) — keys are your job until serials arrive (0024).

5 · How this fits TaskFlow

Every service function in 0020 becomes one sentence here: list→SELECT, add→INSERT…RETURNING, done→UPDATE, rm→DELETE. 0025 runs these from Node (same text, driver delivers); Prisma (0026) generates them. Learn the sentences and ORMs stay transparent forever.

6 · Common mistakes

“Forgot the semicolon.” psql waits with -# prompt, seemingly hung. Fix: type ; + enter — it was waiting for the sentence to end.
“UPDATE without WHERE.” All rows changed, receipt says UPDATE 500. Fix: no antidote except backups — always write WHERE first, SELECT-check on precious tables.
“Quoted a boolean/number.” WHERE done = 'false' — text vs boolean mismatch (empty result, no error!). Fix: types matter in comparisons; strings take quotes, the rest don't.
