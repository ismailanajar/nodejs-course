Schemas rule the rooms

One sitting, one win: hand-checks retire — every input is judged by a schema that names each fault.

⏱ 30–40 minPrerequisites: Lesson 0018 (layers)Objectives: schema · safeParse · 400s
The real problem. Your rooms are filling with typeof spaghetti — title checks here, done checks there, limit checks everywhere, each phrased differently. Validation logic scattered across handlers rots first and lies most. The fix: describe the shape once, judge every input against it, and let the failures describe themselves.

Source + safeParse law (click)

Law: safeParse in servers, never bare parse (which throws — and a throw for user input is using the error lane as validation). Verdict shape: { success: true, data } vs { success: false, error }; error.issues names path + message per fault. Source: Zod docs.

Source + coercion note (click)

URLs carry text only, so query schemas coerce: z.coerce.number() turns "20" into 20, then .int().positive() judges it. Coercion without judgment is laundering — always chain both.

4 · Live demo: bouncers hired (10 min)

npm install zod
# check package.json — tiny, zero-dependency, typed

Create schemas.mjs, then slim two rooms:

// file: schemas.mjs
import { z } from "zod";

export const taskCreate = z.object({
  title: z.string().trim().min(1, "title must be a non-empty string"),
}).strict(); // no mystery keys smuggled in

export const taskUpdate = z.object({
  title: z.string().trim().min(1).optional(),
  done: z.boolean().optional(),
}).strict().refine((o) => Object.keys(o).length > 0, "send at least one field");

export const taskQuery = z.object({
  done: z.enum(["true", "false"]).optional(),
  limit: z.coerce.number().int().positive().max(100).optional(),
});

export function judged(res, verdict) {
  if (verdict.success) return verdict.data;
  res.status(400).json({ error: "invalid input", issues: verdict.error.issues });
  return null; // caller: if (!data) return;
}
// rooms become (imports + wiring assumed):
app.post("/tasks", (req, res) => {
  const data = judged(res, taskCreate.safeParse(req.body));
  if (!data) return; // 400 already sent, with named issues
  const task = { id: `t${Date.now()}`, title: data.title, done: false };
  tasks.push(task);
  res.status(201).json(task);
});
app.get("/tasks", (req, res) => {
  const q = judged(res, taskQuery.safeParse(req.query));
  if (!q) return;
  let list = tasks;
  if (q.done !== undefined) list = list.filter((t) => String(t.done) === q.done);
  if (q.limit !== undefined) list = list.slice(0, q.limit);
  res.json(list);
});
node app.mjs
node -e "const r = await fetch('http://localhost:3000/tasks',{method:'POST',headers:{'content-type':'application/json'},body:JSON.stringify({title:'  '})}); console.log(r.status, JSON.stringify(await r.json()))"
# expected: 400 { error:'invalid input', issues:[{ path:['title'], message:'title must be...' }] }
node -e "const r = await fetch('http://localhost:3000/tasks?limit=abc'); console.log(r.status, JSON.stringify(await r.json()))"
# expected: 400 with issues on limit — coercion judged, not laundered

Why it works: .strict() rejects smuggled keys (clients can't plant admin:true); trim runs before min(1) so whitespace-only fails; judged keeps rooms at two lines — judge-or-leave.

5 · How this fits TaskFlow

Validation retires as a worry and becomes inventory: every new room starts by writing its three photos. Module 5 reuses these exact shapes against database rows; Module 6 adds auth photos (email/password rules). The judged helper survives into middleware form later — same verdict, earlier lane.

6 · Common mistakes

“parse instead of safeParse.” Throws on user input → error lane treats a typo like a crash (500-shape). Fix: safeParse at boundaries, always; reserve throws for programmer bugs.
“Validated body, forgot query.” ?limit=-5 slices weirdness (negative slice = tail!). Fix: every entrance gets a photo — body, query, params, no exceptions.
“Coerced without judging.” Number(x) then trusted — NaN walks in wearing a number costume. Fix: coerce inside the schema so judgment follows automatically.
