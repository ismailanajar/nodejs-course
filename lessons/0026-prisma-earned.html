The real problem. Hand SQL is honest but verbose: every query re-spells columns, joins fan out manually, and refactors mean grep. An ORM doesn't remove SQL — it generates the sentences you already understand from models, and hands back typed objects. Skipping straight here makes magic; arriving now makes machinery.

4 · Live demo: generate + query (12 min)

npm install prisma@7 @prisma/client@7
npx prisma@7 init --datasource-provider postgresql
# writes prisma/schema.prisma + .env (DATABASE_URL lives here now — gitignore it!)

Models (prisma/schema.prisma) — the family, declared:

model User {
  id       String    @id @default(cuid())
  email    String    @unique
  projects Project[]
}
model Project {
  id      String @id @default(cuid())
  name    String
  ownerId String
  owner   User   @relation(fields: [ownerId], references: [id], onDelete: Cascade)
  tasks   Task[]
}
model Task {
  id        String   @id @default(cuid())
  title     String
  done      Boolean  @default(false)
  createdAt DateTime @default(now())
  projectId String
  project   Project  @relation(fields: [projectId], references: [id], onDelete: Cascade)
}
npx prisma@7 migrate dev --name family
# generates db SQL + applies + regenerates client. Inspect prisma/migrations/ — real SQL, readable.
node -e "const {PrismaClient} = await import('@prisma/client'); const p = new PrismaClient();
const u = await u.upsert({ where: { email: 'ada@example.com' }, update: {}, create: { email: 'ada@example.com' } });
console.log(u); await p.\$disconnect()"
# expected: { id: 'c...', email: 'ada@example.com' } — typed row, zero SQL typed

Why it works: migrate dev diffs models vs applied chain and writes the next migration file (chain discipline automated); the client is generated from the same models (drift impossible); .env holds the dial — confirm it's ignored before any commit.

6 · Common mistakes

“Committed .env.” Real DATABASE_URL in git history — rotate the password immediately. Fix: .env in .gitignore from minute one; .env.example with blanks committed instead.
“Edited a migration.” Applied history rewritten → teammates' databases diverge. Fix: new model change = new migrate dev; Prisma authors the file, you review the SQL.
“N+1 via include loops.” Fetching projects then tasks-per-project in a loop (N queries). Fix: one include (single JOIN) — watch query logs until the habit sticks.
